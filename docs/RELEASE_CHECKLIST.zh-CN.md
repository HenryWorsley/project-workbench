# GitHub 发布检查清单

这份清单用于源码公开、测试版发布和桌面安装包发布。任何标记为“阻断项”的内容未完成时，不发布正式版本。

## 当前审计状态

- [x] 公开版使用虚构项目、虚构人员和模拟数据
- [x] 源码未发现内部品牌、真实地点、真实人员或正式项目资料
- [x] `node_modules`、构建目录和视频输出目录已加入 `.gitignore`
- [x] 已建立 README、更新记录、贡献说明和安全策略
- [x] 已建立基础 CI 工作流
- [x] 已确定并添加 `Apache-2.0` 开源许可证
- [x] 首次公开提交前已检查完整 Git 历史和待提交文件
- [x] GitHub 仓库已确定为 `HenryWorsley/project-workbench`，安全问题使用私密漏洞报告入口

## 1. 法律与所有权

- [ ] 确认发布者拥有代码、图标、图片、字体和音乐的发布权
- [ ] 确认依赖许可证与目标许可证兼容
- [x] 选择许可证并在根目录添加标准 `LICENSE` 文件
- [x] 在 README 中写明许可证，不使用含糊的“免费使用”表述
- [ ] 确认产品名称、图标和域名不存在明显冲突
- [ ] 若保留独立品牌权利，在 README 中明确“代码许可证不等于商标授权”

建议：如果希望社区和商业用户都容易采用，可优先评估 `Apache-2.0`；如果要求分发修改版时继续开源，应另行评估 `MPL-2.0` 或 `GPL-3.0`。许可证会影响他人使用和二次分发权利，最终决定应由发布者确认。

## 2. 敏感信息

- [x] 搜索企业名、人员名、地址、客户名、项目编号和真实业务术语
- [x] 搜索邮箱、手机号、IP、域名、账号和本地绝对路径
- [x] 搜索 API Key、Token、证书、私钥、`.env` 和云服务配置
- [x] 检查公开截图和 Release 压缩包
- [x] 检查当前公开 Git 历史
- [ ] 从一个全新目录重新克隆仓库，再做一次独立检查
- [ ] 开启 GitHub Secret Scanning 和 Push Protection（仓库支持时）

推荐发布前扫描命令：

```powershell
rg -n -S "企业名|人员名|客户名|项目编号|真实域名" .
git log --all --stat
git grep -n "待检查词" $(git rev-list --all)
```

## 4. 数据安全

- [ ] 升级前自动备份
- [ ] 数据结构升级失败可以回滚
- [ ] 卸载默认不删除用户数据

每个桌面 Release 至少包含：

```text

更新签名文件
Release Notes
已知问题
```

GitHub 自动生成的 Source code 压缩包不能替代经过验证的安装包。
